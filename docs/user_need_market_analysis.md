# 用户需求贴合度与市场推广分析

本文件用于初赛补充说明、复赛约 2000 字作品说明和答辩材料。涉及问卷人数、满意度、付费意愿等数据时，必须在完成真实调研后回填，不使用虚构数字。

## 一、用户需求贴合度

### 1. 目标用户与场景研究

项目的核心用户是处于择校、专业课复习和复试准备阶段的考研学生，重点关注三类人群：首次考研且缺少信息检索经验的学生、跨专业或跨地区报考导致知识与院校信息差较大的学生、需要同时比较多个院校和专业方向的学生。辅助用户包括考研辅导教师、课程助教及高校招生咨询人员。

项目围绕考研全过程梳理出四个高频场景：

| 用户场景 | 主要困难 | 产品响应 |
| --- | --- | --- |
| 专业知识学习 | 教材、大纲和解析分散，通用模型回答缺少依据 | 按专业和科目检索知识，输出解释、考点、易错点与引用来源 |
| 真题与主观题解析 | 只看答案难以理解得分步骤，不同专业题型差异明显 | 识别考试方向，生成考点定位、作答步骤和复习建议 |
| 择校与招生信息查询 | 招生简章、专业目录、参考书和复试通知分布在不同官网，且年度变化快 | 优先检索研招网、研究生院和学院官网，显示年份、来源和时效风险提示 |
| 个性化复习规划 | 学生基础、目标院校和剩余时间不同，通用计划可执行性低 | 根据专业、目标、基础和周期生成分阶段计划，并支持继续追问调整 |

上述场景研究来自对研招网、院校研究生院、学院官网的信息结构及考研完整决策流程的梳理。当前原型选择计算机 408、通信工程、法学三个差异较大的专业方向，以及沈阳工业大学、北京理工大学、上海交通大学、清华大学四所院校进行验证，覆盖统考知识、工程类专业知识、法学主观题和不同层次院校的信息查询需求。

### 2. 需求与功能的对应关系

项目并非提供无边界的通用聊天，而是将需求拆成知识问答、真题解析、院校咨询、复习规划四类 Agent 工作流。系统回答同步返回引用、来源链接、置信度、资料年份和风险提示；当问题涉及“今年”“最新”“招生人数”“分数线”“参考书”等时效字段时，提示用户以当年官方通知为准。这一设计直接解决普通搜索需要反复打开网页、通用大模型容易混淆年份和回答依据不透明的问题。

项目现有 Web 工作台和 HTTP Skill 接口已经能够支持四类场景演示。后续将采用“问卷、半结构化访谈、可用性测试”验证需求：问卷了解资料查找耗时、主要困难和功能优先级；访谈还原真实备考流程；可用性测试记录任务完成率、查询耗时、引用点击率和回答满意度。测试结果将用于调整知识覆盖、交互流程和模型评测集。

### 3. 可直接用于申报书的正文

本项目面向考研学生在专业课学习、真题解析、院校信息核验和复习规划中的真实需求。前期通过梳理研招网、院校研究生院及学院官网的信息结构，并按考研决策流程分析用户任务，发现考生普遍需要在教材、大纲、招生简章、专业目录和复试通知之间反复检索；招生人数、考试科目、参考书和分数线等信息又具有明显的年度时效性。首次考研、跨专业和跨地区考生尤其容易面临资料分散、筛选成本高、回答依据不清和年份混淆等问题。为此，作品将需求拆分为专业知识问答、真题解析、院校咨询和复习规划四类 Agent 场景，回答同时提供引用来源、年份标记、置信度和风险提示。项目以计算机 408、通信工程、法学及四所示例院校构建原型，既覆盖不同题型和知识结构，也验证院校数据接入方式的可迁移性。复赛阶段将通过真实问卷、用户访谈和任务测试，以查询耗时、任务完成率、引用有效率和满意度持续验证需求贴合度。

## 二、市场价值及推广性

### 1. 市场价值

考研服务具有用户规模大、信息决策频繁和专业差异明显的特点。本项目的价值不只是生成答案，而是降低资料搜集与核验成本，把官方信息、专业知识和个人计划组织成可追溯的服务。对个人用户，产品能够减少重复搜索并提升复习效率；对辅导机构，能够沉淀经过教师审核的知识资产，降低助教重复答疑成本；对高校招生部门，可作为官方招生资料基础上的智能咨询入口，分担常见问题咨询压力。

项目的数据结构和 Agent 工作流具有较强泛化能力。新增专业时可复用“科目、知识点、题型、来源”的知识模板；新增院校时可复用“研招网、研究生院、学院官网”的来源适配流程；新增年度时可通过年份版本和过期风险标记更新资料。相同技术还可迁移到公考、法考、职业资格考试和高校课程问答等场景。

### 2. 产品与推广模式

项目拟采用“C 端工具、B 端服务、开放生态”三层推广模式：

| 模式 | 产品形式 | 主要价值 |
| --- | --- | --- |
| C 端个人服务 | 基础问答与官方信息核验免费，专业知识包、学习报告和深度规划提供增值服务 | 低门槛获客，依靠真实使用反馈迭代产品 |
| B 端机构服务 | 为高校、图书馆和正规辅导机构提供私有知识库、教师审核后台、API 或本地化部署 | 保护机构资料，减少重复答疑，形成稳定服务收入 |
| 开放生态 | 开放基础 Skill 接口、数据规范和部分评测集，吸引教师与开发者扩展专业适配包 | 降低扩展成本，提高专业和院校覆盖速度 |

推广分为三个阶段。第一阶段以当前三个专业和四所院校开展小规模校园试用，通过学生社群、课程教师和校内学习组织收集真实任务反馈；第二阶段与辅导机构、高校图书馆或招生咨询部门开展联合试点，形成可量化案例；第三阶段复制标准化知识模板和昇腾部署方案，扩展更多专业、院校和考试类型，并通过开源社区和昇腾生态活动扩大技术影响力。

### 3. 潜在合作对象

- 高校研究生院、招生办公室和二级学院：建设基于本校官方资料的招生咨询知识库。
- 高校图书馆、学习中心和学生组织：提供校内试用、需求调研和备考资源服务。
- 正规考研辅导机构及专业课教师：共建经审核的课程知识库、题目解析和学习计划。
- 教育出版社及数字内容平台：在获得授权的前提下接入教材、题库和课程内容。
- 华为昇腾、ModelArts及相关算力合作伙伴：支持 Qwen3.5 的训练、推理、私有化部署和性能优化。
- 开源社区和开发者团队：共同建设院校数据适配器、评测集和新的专业 Skill。

研招网和院校官网当前是公开信息来源，不表述为已经建立合作；涉及教材、题库和课程内容时必须获得版权授权。

### 4. 可直接用于申报书的正文

项目具有面向个人、教育机构和高校服务部门的多层市场价值。个人用户可使用带来源的专业问答、院校信息核验和个性化复习规划，减少重复检索成本；辅导机构可将教师审核资料沉淀为私有知识库，降低助教重复答疑压力；高校招生部门可基于本校官方材料建设智能咨询入口。系统采用标准化知识卡片、年份版本管理、场景 Agent 和模型服务解耦架构，新增专业、院校与年度数据时无需重构系统，因此具备较好的可普及和可泛化能力。推广上采用“校园试用验证、机构联合试点、标准方案复制、开放生态扩展”的路径，并形成 C 端增值服务、B 端私有化部署与 API 服务相结合的模式。潜在合作对象包括高校研究生院和学院、高校图书馆、正规辅导机构、专业课教师、教育出版社、昇腾算力与云服务伙伴及开源社区。所有招生信息坚持官方来源核验，教材和题库内容则在获得授权后接入，以保证产品长期合规运营。

## 三、复赛前需要补齐的真实证据

1. 收集不少于 50 份有效问卷，覆盖至少三个专业方向；人数是建议目标，最终材料填写真实数量。
2. 完成 8 至 12 名目标考生的半结构化访谈，保留匿名访谈记录和需求编码表。
3. 邀请 10 至 15 名用户完成四类典型任务，对比传统搜索与本系统的任务时间和完成质量。
4. 记录任务完成率、平均查询耗时、引用有效率、回答满意度、继续使用意愿等指标。
5. 形成一页用户画像、一张需求优先级图和一张测试结果对比图，作为复赛说明书与答辩证据。
