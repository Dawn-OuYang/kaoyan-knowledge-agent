# 研招网数据接入策略

读取日期：2026-07-21

来源：首页 `https://yz.chsi.com.cn/`，院校库 `https://yz.chsi.com.cn/sch/`，招生简章 `https://yz.chsi.com.cn/kyzx/zsjz/`，专业库 `https://yz.chsi.com.cn/zyk/`，硕士目录 `https://yz.chsi.com.cn/zsml/`，网报公告 `https://yz.chsi.com.cn/sswbgg/`。

## 1. 为什么要接入研招网

研招网是本项目“院校咨询 Agent”和“招生信息核验”的优先官方来源。它适合回答：

- 某学校是否有研究生招生单位信息。
- 某学校的招生简章、网报公告、在线咨询入口在哪里。
- 某专业属于什么类别、专业代码是什么。
- 某专业在某地区、某学校是否出现在硕士专业目录中。
- 报名、网报、复试调剂、信息公开等官方流程入口在哪里。

研招网不适合作为唯一来源回答：

- 具体教材细节、专业课知识点讲解。
- 目标院校学院官网才发布的最新复试细则。
- 真题答案和复习规划。

因此，本项目采用“研招网兜底核验 + 院校官网细节补充 + 专业课知识库回答”的组合。

## 3. 数据采集原则

初赛阶段建议先做“人工整理 + 结构化导入”，不做大规模自动爬取：

1. 选择 3-5 所目标院校做样例：如北京大学、清华大学、中国人民大学、北京邮电大学、武汉大学。
2. 每所院校整理 5 类资料：院校库页面、招生简章、硕士目录查询结果、学院官网招生通知、复试/录取办法。
3. 每条资料必须保存：标题、URL、发布日期、年份、学校、专业、信息类型、摘要、更新时间。
4. 对“人数、分数线、参考书、考试科目”强制标注年份和来源。
5. 回答中不直接说“最新一定是”，而说“截至资料更新时间，来源显示……请以当年官方通知为准”。

## 5. 接入步骤

### 阶段 A：数据源注册

已新增 `data/source_registry.json`，用于记录研招网各入口和用途。

### 阶段 B：人工样例卡片

已新增 `data/source_cards_sample.json`，用于整理少量官方资料卡。这个文件适合你后续汇报时展示“我们不是胡答，而是每条信息都有来源卡”。

### 阶段 C：导入知识库

已新增 `scripts/import_source_cards.py`，可把资料卡转换成 `data/knowledge_base.json` 的条目格式。后续真实资料补齐后执行一次即可导入。

### 阶段 D：评测

用 `reports/accuracy_log_template.md` 验证：

- 院校信息是否能检索到正确来源。
- 涉及时效信息是否主动提示年份。
- 回答是否避免把招生人数、参考书等说死。

## 6. 答辩话术

评委问“考研数据从哪里来？”

回答：

> 我们把数据源分成三层。第一层是研招网，用于院校库、招生简章、硕士目录、网报公告等官方核验；第二层是目标院校研究生院和学院官网，用于补充具体学院、专业方向、参考书、复试细则等细节；第三层是专业课知识库和真题解析，用于知识点问答。系统回答时会保留来源、年份和更新时间，对于招生人数、分数线、参考书这类时效信息会提示以当年官方通知为准。

评委问“你们怎么防止幻觉？”

回答：

> 我们不让模型直接凭记忆回答院校信息，而是先检索研招网和院校官网资料卡，再把来源片段交给 Agent 生成回答。没有检索到来源时，系统会降置信度并提示需要补充官方资料；涉及时效数据时会强制标注年份和来源。
