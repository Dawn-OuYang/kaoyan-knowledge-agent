# 初赛项目创意书初稿

## 项目名称

考研各专业知识库问答智能体

## 项目背景

考研备考资料分散，专业课差异大，院校信息更新快。考生在备考过程中需要反复查找考试大纲、招生简章、参考书、真题解析、复试细则等资料，但这些资料来源分散、格式不统一、时效性强。普通大模型虽然能回答问题，但容易出现依据不明、回答泛化、年份信息混淆和幻觉问题。

本项目面向考研专业课备考场景，构建可溯源知识库问答智能体。系统通过 RAG 检索增强、场景化 Agent 工作流和昇腾大模型推理适配，为考生提供专业知识问答、真题解析、院校信息核验和个性化复习规划。

## 项目目标

1. 建立面向考研专业课的结构化知识库。
2. 实现带引用来源的智能问答，降低幻觉风险。
3. 设计知识问答、真题解析、院校咨询、复习规划四类 Agent。
4. 参考附件要求接入 MindSpeed-MM/Qwen3.5 技术路线。
5. 在昇腾 NPU 环境下完成模型推理、功能验证、精度日志和性能分析报告。

## 核心功能

- 专业知识问答：按专业、科目、知识点回答问题。
- 真题解析：给出考点定位、作答步骤和易错提醒。
- 院校咨询：对招生目录、参考书、复试要求等信息进行来源核验。
- 复习规划：根据目标院校、剩余天数、当前基础生成分阶段计划。
- 引用溯源：展示知识来源、检索片段和置信度。
- 风险提示：对“最新、今年、分数线、招生人数”等时效信息主动提醒。

## 技术路线

```text
考研资料
  -> 文档清洗与知识库构建
  -> RAG 检索与重排序
  -> Agent 路由
  -> MindSpeed-MM/Qwen3.5 推理服务
  -> 昇腾 NPU 性能验证
  -> 带引用回答与答辩日志
```

当前 MVP 已完成本地 Web 演示、样例知识库、轻量检索、四类 Agent 模式和引用展示。附件 7 官方 `MindSpeed-MM` 样例已完成副本读取和结构分析，项目已新增 `ascend/` 目录对齐 Qwen3.5 权重转换、DCP 加载、FSDP 微调配置、训练启动脚本和考研 SFT 样例数据。后续将在昇腾 NPU 环境复跑，并按附件 3、附件 5、附件 6 输出性能与精度验证材料。

## 昇腾赛道适配

本项目将昇腾适配作为技术主线，而不是简单部署说明：

1. 使用 MindSpeed-MM/Qwen3.5 作为模型推理与多模态扩展方向。
2. 参考附件 7 官方 `examples/qwen3_5` 流程完成 HuggingFace 权重到 DCP 权重转换。
3. 使用 `torchrun mindspeed_mm/fsdp/train/trainer.py` 和项目适配配置完成考研问答数据微调。
4. 使用 COCO 数据集或官方样例数据进行基础功能与精度验证，多模态扩展时可迁移 Qwen3VL 样例。
5. 使用考研问答评测集进行业务场景验证。
6. 输出精度测试日志和性能分析报告，指标包括 step time、吞吐、loss、NPU memory、首 token 延迟、总响应时间和引用命中率。

## 创新点

- 场景创新：聚焦考研专业课，而不是泛化问答。
- 可靠性创新：回答必须引用知识来源，并标记时效风险。
- Agent 创新：不同问题进入不同工作流，而不是单一提示词回答。
- 工程创新：应用层与昇腾推理层解耦，便于替换模型和扩展知识库。
- 验证创新：同时覆盖功能、精度、性能三类指标。

## 预期成果

- 可运行 Web 演示系统。
- 考研专业知识库样例。
- 昇腾推理适配方案。
- 功能验证记录。
- 精度测试日志。
- 性能分析报告。
- 项目创意书和答辩材料。

## 当前风险与解决方案

| 风险 | 影响 | 解决方案 |
| --- | --- | --- |
| 附件 7 官方代码较完整，直接融合成本高 | 若盲目复制会造成工程臃肿、难以解释 | 只抽取官方 Qwen3.5/Qwen3VL 运行链路、配置字段、日志指标，项目侧保留清晰 `ascend/` 适配骨架 |
| 本地暂无昇腾 NPU 环境 | 不能立刻产生真实 NPU 性能数据 | 先完成接口封装和报告模板，后续上昇腾环境补测 |
| 真实考研资料尚未整理 | 业务精度不足 | 先建样例库，再逐步导入大纲、真题、招生简章 |
| 年份信息变化快 | 容易误导用户 | 对时效信息强制标注年份和官方来源 |
